# AGENTS.md — www-getkist-com

The documentation site for the getkist organisation, at
[www.getkist.com](https://www.getkist.com). Built with **VitePress**; the site
root is `src/`, not the repo root.

## Layout

| Path | What lives there |
| --- | --- |
| `src/.vitepress/config.js` | Site config, nav and sidebar. A new page is not reachable until it is added here. |
| `src/.vitepress/theme/`, `src/.vitepress/data/` | Theme customisation and data files |
| `src/index.md` | Home page |
| `src/guide/` | Hand-written prose — getting started, installation, configuration, architecture, caching, core actions, plugin development, editor setup, cookbook, best practices, comparison, migrate-from-gulp/grunt |
| `src/plugins/` | One page per `@getkist/action-*` package, plus `index`, `registry`, `using-plugins` |
| `src/api/reference/` | **Generated by TypeDoc from the `kist` package. Never hand-edit.** |
| `src/projects/`, `src/media/`, `src/public/` | Other content and static assets |
| `scripts/sync-docs.js` | Copies and rewrites the TypeDoc output into `src/api/reference/` |

## Commands

```bash
npm install
npm run docs:dev       # local dev server
npm run docs:build
npm run docs:preview
npm run sync:api       # runs `npm run docs` in ../kist, then sync:docs
npm run sync:docs      # copy already-generated TypeDoc output
npm run lint           # eslint src/**/*.ts
npm run format
```

## The API reference is generated *and committed*

This is the main thing to get right here. `src/api/reference/` is TypeDoc
output from the `kist` package's TypeScript sources, and it is committed
because the deploy workflow checks out only this repository and cannot
regenerate it.

To change an API doc page, **edit the doc comment in the `kist` repo**, then:

```bash
# with a kist checkout beside this one, or KIST_REPO pointing at it
npm run sync:api
```

`scripts/sync-docs.js` does three things on the way in, so a hand-copied file
will not match: it replaces TypeDoc's `README.md` with a short index page,
rewrites `.md`-suffixed relative links to extensionless site paths, and stamps
every page with frontmatter marking it generated. Editing a file under
`src/api/reference/` is wasted work — the next sync overwrites it.

## Gotchas

- **The Makefile and the Python config files are template leftovers.** There is
  no Django app, no `pyproject.toml`, no `manage.py`; the Makefile's
  `runserver` / `collectstatic` / `migrate` / `translate-*` targets have
  nothing to act on. The site is VitePress only — use the npm scripts. Do not
  build on those targets, and do not treat `.flake8`, `.pylintrc`, `mypy.ini`,
  `pytest.ini`, `tox.ini`, `poetry.toml` etc. as live configuration.
- The repo root README's logo URL points at the `master` branch of `brand`
  while every other repo uses `main`.
- Plugin pages under `src/plugins/` mirror the sibling `kist-action-*` repos.
  Adding a plugin means adding a page here *and* wiring it into the sidebar in
  `src/.vitepress/config.js`.
- The docs are organised along Diátaxis lines (tutorial / how-to / reference /
  explanation); keep a new page in the section that matches its kind rather
  than mixing modes in one file.
